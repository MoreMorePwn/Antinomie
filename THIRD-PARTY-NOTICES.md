## Embedded analysis rules and engines

The triage Detection adapter also invokes optional, separately installed
[Suricata](https://github.com/OISF/suricata),
[pySigma](https://github.com/SigmaHQ/pySigma) and its
[SQLite backend](https://github.com/SigmaHQ/pySigma-backend-sqlite).
These tools are not bundled. Rule packs are downloaded only from the public
rules catalog when a person uses Rule manager, and they keep their upstream
terms. The sigma_scan.py adapter is original project MIT material. The adapter
uses the public pySigma API; no upstream implementation was copied. Production
scans do not embed Antinomie-authored starter collections. A published pack
archive carries the upstream license texts and notices that apply to the
rules inside it. Including those notices does not establish complete legal
clearance for the application. Suricata and pySigma stay optional external
tools and are not bundled.

The static-analysis worker can load an installed community pack. It does not

## Other components and release gate

The 0.6.0 and 0.6.1 archives include the shared Linux dependency notice inventory in
`LICENSES/third-party/locked-dependencies-0.6.0.tar.gz`. It records the 459
resolved third-party crates, checked against the locked package checksums,
their retained upstream license/notice texts and the embedded font/rule notices.
Two published MIT packages provide their declaration without a separate license
text; their unchanged published packages and canonical MIT terms are retained.
The inventory records the exact provenance and preserves combined license terms.
It contains public third-party material, without Antinomie's private host source.
The third-party Cargo.lock entries are unchanged in 0.6.1; only the two project
package versions changed. The current Rust 1.98.1 standard-library notice is
retained separately in
[Rust-Standard-Library-COPYRIGHT.html](LICENSES/third-party/Rust-Standard-Library-COPYRIGHT.html);
the inventory's earlier snapshot remains intact. The new static resource
collector's musl notices are listed below.

The 0.6.2 Properties worker computes similarity hashes in process with two
new pure-Rust crates, `fuzzyhash 0.2.2` (MIT, ssdeep-compatible; notice in
[fuzzyhash-MIT.txt](LICENSES/third-party/fuzzyhash-MIT.txt)) and `tlsh2 1.1.0`
(Trend Micro TLSH port; Apache-2.0 OR BSD-3-Clause, with the BSD-3-Clause option
selected; license text in [tlsh2-LICENSE.txt](LICENSES/third-party/tlsh2-LICENSE.txt)
and notice in [tlsh2-NOTICE.txt](LICENSES/third-party/tlsh2-NOTICE.txt)), both
copied unmodified from the locked crate distributions. Neither has runtime
dependencies. They are new relative to the 0.6.0 dependency inventory above.

The 0.6.2 UI directly uses the already locked `chrono 0.4.45` (MIT OR Apache-2.0)
and its existing local timezone support for host-clock presentation. No new
third-party package version is introduced by this dependency edge. The retained
Cargo source/notice inventory includes these packages under their upstream terms.

The `MoreMorePwn/antinomie-bases` Hugging Face bucket is reserved for the VM
image catalog and required image files. Guest kernel source, exact
bootstrap/desktop package sources and guest notices belong in a separate
publication. Release notes must provide the verified source location before
the release is published. The source inventory associates each distributed
base with its exact kernel configuration, patch series and package versions.

The 0.7.0 debugger serves the GDB Remote Serial Protocol with original code:
the framing, packet dispatch, process-qualified thread ids, all-stop and non-stop
modes and the stop-reply grammar are written from GDB's published protocol
documentation, with no third-party protocol library, and nothing was copied from
gdb, gdbserver (GPL-3.0), QEMU's gdbstub or any other implementation. GDB, IDA,
Ghidra and radare2 are separate programs the user runs and connects to the local
socket; none is bundled or linked. The kernel debug engine
(`kernel/antinomie/debug*.c`) is original GPL-2.0-only code.

Static-analysis executable parsing uses `object 0.40.0` with read/std features
only (no write, build or automatic compression). The MIT option is selected;
its unmodified locked crate notice is retained in
[object-MIT.txt](LICENSES/third-party/object-MIT.txt). Generic byte analysis is
original code. Optional external analysis tools and isolation utilities retain
their own terms and are not relicensed or bundled by this dependency addition.

The native workspace uses `egui_dock 0.16.0` under MIT. Its unmodified crate
notice is retained in [egui-dock-MIT.txt](LICENSES/third-party/egui-dock-MIT.txt).
The adapter for separate operating-system viewports is original project code;
the library's ordinary floating windows alone are not native windows.

The recording browser uses `rusqlite 0.40.2` and `libsqlite3-sys 0.38.2`;
their identical MIT copyright/permission text is retained in
[rusqlite-MIT.txt](LICENSES/third-party/rusqlite-MIT.txt), copied from both
locked crate distributions. SQLite is linked from the system, not bundled by
this build. Its upstream code is public domain; see
[SQLite copyright](https://www.sqlite.org/copyright.html). Packaging must still
inventory the actual library shipped and the crates' transitive dependencies.
The core and UI use `vt100 0.16.2` for terminal persistence and scrollback,
including corrected history offsets and cursor restoration after resizing;
the version update does not change its upstream MIT terms. The copyright and
permission notices for `vt100` and its updated parser dependency `vte 0.15.0`
(MIT option selected) are copied from the locked crate distributions in
[vt100-MIT.txt](LICENSES/third-party/vt100-MIT.txt) and
[vte-MIT.txt](LICENSES/third-party/vte-MIT.txt).

Malware samples are read from (and MalShare's samples written into) AES
archives with the `zip`
crate's `aes-crypto` feature, which brings the RustCrypto crates `aes`,
`cipher`, `pbkdf2`, `hmac`, `sha1`, `digest` and their helpers (`block-buffer`,
`crypto-common`, `inout`, `hybrid-array`, `cpufeatures`, `cpubits`, `cmov`,

and `constant_time_eq` (CC0-1.0, MIT-0 or Apache-2.0). Samples themselves are
downloaded by the user with their own API keys, from MalwareBazaar under
abuse.ch's terms and from MalShare (malshare.com) under MalShare's terms, which
ask that MalShare is credited as the source; each sample keeps its source.
Antinomie hosts and redistributes none.

The launch module directly uses already-locked `x11rb 0.13.2` and `rustix 1.1.5`
for bounded X11/XWayland window sizing and deadline-aware polling. MIT options
are selected; original notices are retained in
[x11rb-MIT.txt](LICENSES/third-party/x11rb-MIT.txt),

The Disks tab reads a stopped VM's guest filesystem in process with
`ext4-view 1.0.0` (Nicholas Bishop, Google LLC; MIT OR Apache-2.0, with the MIT
option selected; read-only, `forbid(unsafe_code)`). The reader runs only in the
sandboxed `antinomie-monitor --disk-reader` worker. Its notice is retained
unmodified from the locked crate distribution in
[ext4-view-MIT.txt](LICENSES/third-party/ext4-view-MIT.txt). Its dependencies
`bitflags` and `crc` were already locked (MIT OR Apache-2.0 each) and are
covered by the shared inventory above. `qemu-img` (QEMU, GPL-2.0-or-later and
other terms), bubblewrap and util-linux `prlimit` are external tools the tab
runs; none is bundled or linked.

Rust crates, linked system libraries and external tools retain their own terms.
Use the locked Cargo metadata and actual packaged artifacts, not just the
application manifest, to inventory a release. The source workspace's MIT
metadata describes its own crates, not all dependencies.

Optional packet display filtering and HTTP/DNS triage invoke an independently
installed Wireshark TShark executable, licensed under GPL-2.0-or-later, through
its command-line interface with PCAP input and field output. Antinomie's host
archive does not include or link Wireshark code. The installed util-linux
`prlimit` command bounds these external processes; its upstream terms remain
applicable. Distributors who include either tool must preserve its notices and
provide its required source arrangement separately.

The image builder uses Linux, BusyBox, e2fsprogs utilities and guest libraries.
Kernel/BusyBox/e2fsprogs GPL and library-specific terms still apply. Before
publishing executables or guest images, review every distributed component,
collect its applicable notices, and provide matching source or another valid
license-compliant source arrangement when required. Do not label an entire
guest image MIT or claim that this notice inventory completes that review.

The optional Debian desktop pipeline uses external libguestfs tools and an
authenticated Debian template/package repository. These tools are not copied
into the monitor ELF. The generated guest retains `/usr/share/doc/*/copyright`,
package/version inventory and template/build provenance; Debian packages,
Xfce, Xorg, fonts and libraries retain their individual upstream terms. A local
development image is not a license-cleared redistribution bundle. Distributing
it requires the same component-specific notice/source review above, including
the exact patched kernel build.

## Temporary guest resource collector (0.6.1)

From 0.7.0 the collector is carried only for bases of revision 16 and earlier;
revision 17 kernels measure resources themselves.

The embedded x86-64 executable is original MIT project code compiled statically
with musl libc (`musl-tools`). musl's MIT and
file-specific notices are retained in
[libc/musl-copyright.txt](LICENSES/third-party/libc/musl-copyright.txt), copied
from the build's installed package copyright inventory. The source checkout's
retained copy originates from Debian 1.2.5-3; release archives retain the actual
build copy and record its package version in BUILD-INFO.json. The collector does not
embed glibc or require a guest dynamic linker. Retain this notice with binaries.
