# Project layout and retained artifacts

The product repository contains maintainable source, reproducible build tooling,
tests, pinned inputs and required notices. The separate documentation repository
contains the authoritative guide, task board, research and historical evidence.

| Repository path | Purpose | Retention |
|---|---|---|
| `src/antinomie/monitor/` | Rust workspace, host libraries, desktop UI and protocol | Tracked source and Cargo lockfile |
| `src/antinomie/core/` | Portable kernel patch series | Tracked source |
| `src/antinomie/patches/` | Generated adapter-specific Quilt patches | Tracked, regenerated by the author/export workflow |
| `src/antinomie/packaging/` | Adapter definitions and kernel configs | Tracked source |
| `src/debian/` | Pinned Debian source metadata and fetched inputs | Keep verified input archives; large fetched archives are ignored |
| `scripts/` | Reusable build, release and maintenance entry points | Tracked; experimental helpers belong in a private archive |
| `tests/` | Maintained test programs, fixtures and CI harnesses | Tracked source; generated results stay outside it |
| `docs/` | Implementation contract and repository-specific layout | Tracked; no competing task board |
| `assets/`, `LICENSES/` | Shipped assets, provenance and license texts | Tracked; notices are required distribution content |
| `.github/` | CI, release and nightly automation | Tracked |
| `work/` | Recreated kernel author/build trees, temporary QA and staging | Disposable after retaining required inputs, work and evidence |
| Cargo `target/` | Rust compiled output | Disposable; dependency lockfiles remain tracked |

Keep large retained material in a sibling workspace, outside tracked source:

```text
project/
  source/                    product Git checkout
  website/                   website Git checkout
  docs/                      pointer to the existing documentation checkout
  releases/X.Y.Z/            published archive, checksum, provenance, runnable package
  bases/X.Y.Z/busybox/       published immutable image bundle
  bases/X.Y.Z/debian-gnome/  published immutable image bundle
  cache/                     verified rebuild inputs and reusable build cache
  archive/                   release evidence, source/notices and historical scripts
  tools/                     local launchers and workstation-specific helpers
```

This is a local storage convention, not a new application setting. User data
stays in the application's existing data directories, outside this workspace.
Do not move or delete user VM overlays, snapshot chains, recordings or exported
analysis projects as build cleanup. Verify backing chains and process ownership
before removing any temporary QA image. Preserve active executables and paths.

Before removing worktrees, preserve unique commits and uncommitted work. Retain
verified Git bundles when retiring kernel author history; bootstrap recreates the
current author tree from the durable patch series. Retain small manifests, test
summaries, logs, screenshots and useful script source; remove stale sockets,
PIDs, pycache, temporary captures/images, duplicate staging and superseded
executables. Historical scripts need review before reuse: do not execute old
publication scripts or infer authorization from their archived presence.

Every new version uses a fresh `release-X.Y.Z` branch. Invoke
`scripts/new-release.sh X.Y.Z` from the current clean release branch before
implementing it. Release archives and image catalogs have independent publishing
steps. The public image bucket contains only image bundles/catalog metadata;
source/license distributions belong in their separately authorized location.
